# Анализ структуры хранилища данных Кольской ВЭС

## Описание

Этот документ описывает структуру файлового хранилища архивов данных вибродиагностики для ветротурбин SMP12C.

## Путь к хранилищу

```text
D:\Работа [Кольская ВЭС]\SMP_SGRE\RAW_DATA
```

## Ожидаемая структура

```text
RAW_DATA/
├── 202509/               # год + месяц (YYYYMM)
│   ├── 03/               # день (DD)
│   │   ├── W1436 WTG6 SMP_RWD_20250903.zip
│   │   ├── W1438 WTG8 SMP_RWD_20250903.zip
│   │   └── ...
│   ├── 04/
│   │   └── W1436 WTG6 SMP_RWD_20250904.zip
│   └── ...
├── 202510/
│   ├── 01/
│   └── ...
└── ...
```

## Паттерны имён архивов

Адаптивный сканер распознаёт следующие паттерны:

|Паттерн|Пример|Описание|
|---|---|---|
|`WTG(\d{1,2}).*?(\d{8})`|`WTG6_SMP_20250903.zip`|WTG + дата|
|`W(\d{4}).*?WTG(\d{1,2}).*?(\d{8})`|`W1436 WTG6 SMP_RWD_20250903.zip`|W#### + WTG + дата|
|`SMP_RWD.*?(\d{8})`|`SMP_RWD_20250903.zip`|SMP_RWD + дата|
|`SMP_RW.*?(\d{8})`|`SMP_RW_20250903.zip`|SMP_RW + дата|
|`(\d{8})`|`archive_20250903.zip`|Просто дата|

## Структура ZIP-архива

Каждый ZIP-архив содержит файлы `.rd2` для нескольких датчиков (1-8) с различными типами фильтров:

```text
W1436 WTG6 SMP_RWD_20250903.zip
├── SENSOR_01_FILTER_W.rd2    # Датчик 1, НЧ фильтр (0.1-10 Гц)
├── SENSOR_01_LOW_W.rd2       # Датчик 1, ВЧ фильтр (10-1000 Гц)
├── SENSOR_01_HIGH_W.rd2      # Датчик 1, ВЧ(ф) фильтр (0-12 кГц)
├── SENSOR_02_FILTER_W.rd2    # Датчик 2, НЧ
├── ...
└── SENSOR_08_HIGH_W.rd2      # Датчик 8, ВЧ(ф)
```

### Типы фильтров

|Тип|Обозначение|Диапазон частот|Назначение|
|---|---|---|---|
|FILTER|`_FILTER_`|0.1-10 Гц|Низкочастотный (НЧ)|
|LOW|`_LOW_`|10-1000 Гц|Высокочастотный (ВЧ)|
|HIGH|`_HIGH_`|0-12 кГц|Высокочастотный (ф)|

### Датчики

|№|Описание|
|---|---|
|1|Главный вал, радиальное направление|
|2|Передняя нижняя часть редуктора|
|3|Средняя нижняя часть редуктора|
|4|Выход трансмиссии, радиальное направление|
|5|Выход трансмиссии, осевое направление|
|6|Подшипник генератора со стороны ротора, осевое направление|
|7|Подшипник генератора со стороны ротора, радиальное направление|
|8|Подшипник генератора, осевое направление|

## Формат файла .rd2

Файлы `.rd2` имеют текстовый CSV-подобный формат:

```text
12345, 2025-09-03 12:00:00, WTG6, WTG6, SENSOR_01
Sampling Time: 0.0000390625 s, Sampling Frequency: 25600 Hz, Samples: 25600, Duration: 1.0 s
Generator Speed: 1500 RPM, Active Power: 2500 kW, Wind Speed: 12.5 m/s, Cumulative Power: 123456 kWh
Device: SMP12C, SN: 12345, MAC: 00:11:22:33:44:55, IP: 192.168.1.100, FW: 1.2.3
Config: 1, Table: 1, Layout: 1, Exception: 0, PLC: 192.168.1.1
0, 0.000000, 0.123
1, 0.000039, 0.456
2, 0.000078, 0.789
...
```

### Метаданные (первые 5 строк)

1. **Основная информация**: record_number, record_datetime, turbine_id, wtg_id, sensor_name
2. **Параметры дискретизации**: Sampling Time, Sampling Frequency, Samples, Duration
3. **Параметры турбины**: Generator Speed, Active Power, Wind Speed, Cumulative Power
4. **Информация об устройстве**: Device, Serial Number, MAC, IP, FW version
5. **Конфигурация**: Config Number, Table Version, Layout Version, Exception, PLC IP

### Данные (остальные строки)

```text
индекс, время (сек), значение (мм/с)
```

## Алгоритм сканирования

1. **Рекурсивный обход** каталога (макс. глубина 6 уровней)
2. **Поиск ZIP-архивов** по расширению `.zip`
3. **Проверка имени** на соответствие паттернам
4. **Анализ содержимого** архива:
   - Подсчёт `.rd2` файлов
   - Извлечение номеров датчиков
   - Определение типов фильтров
5. **Сохранение метаданных** для отображения в GUI
6. **Дедупликация** (проверка по record_datetime + sensor_id + filter_type)

## Обработка ошибок

|Ошибка|Причина|Решение|
|---|---|---|
|"Каталог не существует"|Неверный путь|Проверить путь в настройках|
|"Повреждённый ZIP-архив"|Файл повреждён|Пропустить, логировать ошибку|
|"В архиве не найдено файлов .rd2"|Неправильная структура|Пропустить, логировать предупреждение|
|"Несоответствие WTG"|Прибор привязан к другой турбине|Ошибка валидации, пропустить|

## Критерии готовности сканера

- ✅ Рекурсивный обход каталогов
- ✅ Распознавание паттернов имён
- ✅ Анализ содержимого ZIP
- ✅ Извлечение метаданных датчиков
- ✅ Логирование процесса
- ✅ Отмена сканирования
- ✅ Сохранение лога в файл
- ✅ Дедупликация архивов
- ✅ Чек-боксы: 6×6 px, белый фон, чёрная галочка

## Интеграция с БД

При включённом режиме PostgreSQL:

1. Сканер находит архивы
2. `DataPersistenceService` обрабатывает каждый архив
3. Проверка дедупликации по `(turbine_id, record_datetime, sensor_id, filter_type)`
4. Сохранение в таблицы: `turbines`, `archives`, `sensor_data`, `analysis_cache`
5. Логирование результатов (добавлено/пропущено/ошибка)

## Тестирование

### Проверка сканирования

1. Открыть **Настройки** → вкладка **Хранилище**
2. Указать путь к `RAW_DATA`
3. Нажать **▶ Сканировать хранилище**
4. Проверить лог на наличие ошибок
5. Убедиться, что найдены все ожидаемые архивы

### Проверка динамического переключения БД

1. Открыть **Настройки** → вкладка **База данных**
2. Включить **Использовать PostgreSQL**
3. Ввести параметры подключения
4. Нажать **Применить**
5. Проверить статус-бар: должен отображаться режим **PostgreSQL**
6. Открыть вкладку **Тренды** — данные должны загружаться из БД
