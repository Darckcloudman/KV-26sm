# Инструкция по тестированию v1.4

## Новые возможности

### 1. Стилизация чек-боксов
- Все QCheckBox имеют белый фон (#FFFFFF)
- Чёрная рамка (#333333)
- Чёрная галочка в режиме checked

### 2. Динамическое переключение режима БД
- Переключение между файловым режимом и PostgreSQL без перезапуска
- Кнопка "Применить" в настройках вместо "Сохранить"
- Индикатор режима в статус-баре

### 3. Адаптивное сканирование хранилища
- Перенесено с Home в Настройки → Хранилище
- Подробный цветной лог процесса
- Прогресс-бар
- Кнопка отмены
- Сохранение лога в файл

### 4. Гибкий парсер архивов
- Распознавание по нескольким паттернам
- Поддержка различной вложенности
- Автоматическое определение датчиков и фильтров

## Тестирование

### Тест 1: Стилизация чек-боксов

1. Запустить приложение
2. Открыть **Настройки**
3. Проверить чек-боксы на всех вкладках:
   - Фон индикатора: белый (#FFFFFF)
   - Рамка: тёмно-серая (#333333)
   - Галочка: чёрная при checked

**Ожидаемый результат**: Все чек-боксы соответствуют стилю.

---

### Тест 2: Динамическое переключение БД

#### Подготовка
1. Убедиться, что PostgreSQL доступен
2. Проверить параметры в `.env`:
   ```
   USE_DATABASE=true
   DB_HOST=localhost
   DB_PORT=5432
   DB_USER=postgres
   DB_NAME=vibrodiag
   ```

#### Шаги
1. Запустить приложение
2. Проверить статус-бар: должен быть "Режим: PostgreSQL (localhost)"
3. Открыть **Настройки** → **База данных**
4. Отключить **Использовать PostgreSQL**
5. Нажать **Применить**
6. Проверить статус-бар: "Режим: Файловая система"
7. Открыть **Настройки** снова
8. Включить **Использовать PostgreSQL**
9. Нажать **Применить**
10. Проверить статус-бар: "Режим: PostgreSQL (localhost)"

**Ожидаемый результат**: Режим переключается без перезапуска, индикатор обновляется.

---

### Тест 3: Сканирование хранилища

#### Подготовка
1. Указать путь к хранилищу в настройках
2. Убедиться, что в хранилище есть ZIP-архивы

#### Шаги
1. Открыть **Настройки** → **Хранилище**
2. Нажать **▶ Сканировать хранилище**
3. Наблюдать за прогрессом:
   - Прогресс-бар заполняется
   - Лог обновляется в реальном времени
   - Цвета сообщений:
     - INFO: серый (#BBBBBB)
     - SUCCESS: зелёный (#00C853)
     - WARNING: жёлтый (#FFD600)
     - ERROR: красный (#DD2C00)
4. Дождаться завершения
5. Проверить сводку в конце лога
6. Нажать **💾 Сохранить лог**
7. Сохранить файл, проверить содержимое

**Ожидаемый результат**: Все архивы найдены, лог подробный, ошибки зафиксированы.

---

### Тест 4: Отмена сканирования

1. Открыть **Настройки** → **Хранилище**
2. Нажать **▶ Сканировать хранилище**
3. Через 5-10 секунд нажать **⏹ Отмена**
4. Проверить лог: должно быть "Сканирование отменено пользователем"

**Ожидаемый результат**: Сканирование останавливается, UI возвращается в исходное состояние.

---

### Тест 5: Индикатор режима в статус-баре

1. Запустить приложение
2. Проверить правую часть статус-бара
3. Должно отображаться:
   - "Режим: PostgreSQL (host)" или
   - "Режим: Файловая система"
4. Цвет текста:
   - PostgreSQL: синий (#448AFF)
   - Файловый: серый (#888888)

**Ожидаемый результат**: Индикатор отображается, цвет соответствует режиму.

---

### Тест 6: Обновление HomeScreen при смене репозитория

1. Открыть приложение в файловом режиме
2. Проверить таблицу архивов на Home
3. Переключиться на PostgreSQL (Настройки → Применить)
4. Проверить, что таблица обновилась (данные из БД)

**Ожидаемый результат**: Данные на Home обновляются при смене репозитория.

---

### Тест 7: Анализ реальных архивов Кольской ВЭС

#### Подготовка
```
Путь: D:\Работа [Кольская ВЭС]\SMP_SGRE\RAW_DATA
Структура:
  202509/03/W1436 WTG6 SMP_RWD_20250903.zip
  202509/03/W1438 WTG8 SMP_RWD_20250903.zip
  ...
```

#### Шаги
1. Указать путь в **Настройки** → **Хранилище**
2. Запустить сканирование
3. Проверить лог:
   - Найденные архивы с WTG идентификаторами
   - Количество датчиков в каждом архиве
   - Количество .rd2 файлов
4. Проверить, что распознаны паттерны:
   - `W1436 WTG6 SMP_RWD_20250903.zip`
   - WTG извлечён: WTG6
   - Дата: 20250903

**Ожидаемый результат**: Все архивы распознаны корректно.

## Тест 8: Просмотр логов приложения (вкладка "Логирование")

#### Шаги
1. Открыть **Настройки** → **Логирование**
2. Проверить панель просмотра логов:
   - Отображаются логи из файла `app.log`
   - Цветовая кодировка уровней:
     - DEBUG: серый (#888888)
     - INFO: белый (#CCCCCC)
     - WARNING: жёлтый (#FFD600)
     - ERROR: оранжевый (#FF6D00)
     - CRITICAL: красный (#DD2C00)
3. Изменить фильтр в выпадающем списке "Фильтр по уровню":
   - Выбрать "ERROR" — должны отображаться только ошибки
   - Выбрать "Все" — все уровни
4. Нажать "🔄 Обновить" — логи перезагружаются
5. Нажать "🗑 Очистить" — отображение очищается
6. Нажать "💾 Сохранить" — сохранить логи в файл
7. Включить/выключить "Автопрокрутка"

**Ожидаемый результат**: Логи отображаются, фильтр работает, кнопки функционируют.

## Известные ограничения

1. **Глубина сканирования**: ограничена 6 уровнями (настраивается в `AdaptiveArchiveScanner`)
2. **Производительность**: при больших хранилищах (>1000 архивов) сканирование может занять несколько минут
3. **Fusion стиль**: требуется `app.setStyle("Fusion")` в `main.py` для корректной отрисовки чек-боксов
